Carry is a working local prototype for gathering privately and bringing one find to one person with context. Its present object is a native iPhone application with a signed share extension, a persistent notebook, saved media, and a portable Bag archive. It is installed on Bradley's paired iPhone for testing. It is not available as a public download.

The proposal emerged during the October 8 forest conversation recorded in [Field Note 41, The Path Remembers](https://cyberdelic.space/project/cyberdelic-os/field-notes/fn-41/). Bradley developed the Bag as a place to gather without immediately sharing, requested cryptographic lineage, and chose a local three-person first edition. He selected Field Guide from five interface studies and Folded Leaf from five icon studies.

## What exists

The application has Bag, Arrivals, and People views. It supports collection, search, private notes and tags, addressed written or spoken context, persistent drafts, receiving, keeping, onward carrying, and permission to reveal earlier crossings. Daily acceptance limits are enforced locally.

Supported capture includes links, writing, photographs, sound, video, and documents. The share extension saves into the Bag before a person decides whether to carry anything. Build 3 reads X posts, YouTube videos, web pages, PDFs, text, supported native document previews, saved media, and Elsewhere contents inside the application.

The three labelled practice people share one installation. Their independent signing keys and local acceptance key allow the exchange and its proofs to be rehearsed. There is no connected delivery service, authenticated account system, or synchronization between iPhones.

The shipped forest and coast images are generated practice studies. The example writing and reader fixtures are synthetic material. They demonstrate the interface and checks rather than documenting a real exchange among three people.

## The portable object

The `.carrybag` format is a bounded stored ZIP containing collected snapshots, the exporting owner's notes and tags, included media, and public proofs for the history that person is allowed to export. It includes no private signing keys and no other person's private Bag. An export can include sensitive collecting notes; its owner chooses where to keep it.

The verifier checks byte commitments, signatures, recipient bindings, and included lineage. An independent Python verifier checks the cryptographic archive separately from the app's CryptoKit implementation. A partial history is a permitted view of the route, not a complete account of every earlier crossing.

Import makes collection copies in the active Bag. It does not take over the old signing identity, recreate past arrivals, or spend a present-day allowance. Preserve the original archive when retaining its complete exported proof set.

Signing keys remain device-bound in Keychain. Notebook data and saved media are excluded from device backup, making an explicit export important before deleting the app. A Bag archive preserves material and proofs; it is not an account-recovery mechanism.

## What has been observed

At the recorded revision, 16 core and capture tests passed, and all eight UI scenarios were verified across simulator runs. These covered local delivery and onward carrying, permissions, persistence, actual public-provider rendering and playback, and readable native files. Signed Release and minimum-runtime builds succeeded. Build 3's physical installation was confirmed independently by the phone's installed-app list.

The locked phone prevented automatic launch. Installation therefore establishes the presence of the app, while physical hands-on use, live microphone recording, real shares from other apps, and a lived interpersonal trial remain unconfirmed in this record. There has been no independent security review or public distribution release.

## Keeping this version

Preserve the exact source revision, generated Xcode project, format and validation documents, approved icon masters, design studies, and exports made during future tests. A compatible iPhone or simulator and a signed build are required to run the application. The software uses Apple frameworks without third-party app SDKs.

Included attachment bytes can survive their original source. External posts and videos still require available providers and a connection. Earlier explanations remain subject to the history permissions represented in a given export, but copies already received cannot be recalled by later withdrawal.

This record identifies the first native Field Guide prototype. A connected service, public release, or future visual geography should receive its own dated record. The landscape of paths and roads remains a design direction; this object supplies local crossings and their permitted lineage.
