What the sources state

I-005 specifies a finite correspondence of seven addressed arrivals. It distinguishes links from included bytes, preserves earlier arrangements, requires explicit saving and file handoff, and keeps publication separate from the private encounter.

BN-006 documents how the prototype embodies those commitments. The browser canvas, Mac companion, and exported HTML share one JavaScript runtime. Seven whole-canvas snapshots preserve the arrangement at each handoff. Included files and the full archive have explicit bounds. Each sealed turn carries a digest over canonical exchange and snapshot data, including the previous digest and referenced asset commitments.

The Builder Note also states the boundary of that evidence. The hashes are unsigned, so a file alone does not authenticate contributors, prove consent, or establish a true timestamp. Unsaved edits remain in memory, separate copies can diverge, and the current static prototype provides neither automatic recovery nor a central authority for accepted history.

What the Cartographer infers

BN-006 is the technical implementation account for I-005. It makes the instrument's conduct inspectable as runtime, data model, archive boundaries, integrity checks, and explicit failure conditions. The relation is strong because both exact publications describe the same named work and directly link to one another.

This relation does not claim that a turn digest authenticates a person, that manual file handoff is reliable enough for a shared service, or that the current prototype resolves recovery, conflicts, privacy, or consent.
