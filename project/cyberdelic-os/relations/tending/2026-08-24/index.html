What the sources state

Open Container Initiative Image Specification 1.1.1 describes a container image through a manifest, an optional index, filesystem layers, and configuration. Its stated purpose is interoperability among tools that build, transport, and prepare an image to run.

The configuration separates ordered filesystem changes from execution parameters. It can record an entrypoint, default arguments, environment, networking, volumes, and other runtime properties. Content descriptors identify referenced bytes by media type, digest, and size, allowing a consumer to verify the retrieved content before use.

The format is not automatically self-contained. Its image layout permits referenced blobs to be absent and retrieved from an external blob store. Content addressability can make an absence detectable without making the missing material available.

What the Cartographer infers

The OCI Image Specification offers a possible technical adjacency to FN-33, The Plate and the Pull. It provides a precedent for distinguishing immutable content from execution configuration, binding dependencies through verifiable descriptors, and representing platform-specific variants without pretending they are one universal environment.

The relation must remain a difference as well as a resemblance. OCI prepares a runnable filesystem for a container runtime and may depend on external blob storage. FN-33 imagines a browser-readable generative plate, authorized pull lineage, public copyability, and an edition that can verifiably end. OCI does not supply those artistic or lineage semantics.
